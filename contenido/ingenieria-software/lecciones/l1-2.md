La **Ingeniería de Software (IS)** es la aplicación de un enfoque **sistemático, disciplinado y cuantificable** para el **desarrollo, operación y mantenimiento** del software. {a Apuntes de Ingeniería de Software · Unidad 1}

## Definición IEEE

> *"La aplicación de un enfoque sistemático, disciplinado y cuantificable para el desarrollo, operación y mantenimiento del software; la aplicación de la ingeniería al software."* — IEEE 610.12 {a Apuntes de Ingeniería de Software · Unidad 1}

## Crisis del software (1968)

Reconocimiento público de problemas sistémicos: sistemas que fallan, exceden presupuesto y plazos, y no cumplen expectativas. La conferencia de la OTAN en Garmisch (1968) acuñó el término "crisis del software". {a Apuntes de Ingeniería de Software · Unidad 1}

## Capas de la Ingeniería de Software

```mermaid Capas de la IS
flowchart TD
  Cal[Calidad<br/>Base cultural de mejora continua]
  Pro[Proceso<br/>Marco de trabajo con hitos y control]
  Met[Métodos<br/>Cómo construir técnicamente el software]
  Her[Herramientas<br/>Soporte automatizado (CASE)]
  Cal --> Pro
  Pro --> Met
  Met --> Her
```

| Capa | Qué es | Ejemplos |
|---|---|---|
| **Calidad** | Base cultural de mejora continua | *Continuous improvement*, *craftsmanship* |
| **Proceso** | Marco de trabajo con hitos y control | Ciclo de vida, *milestones*, *gates* |
| **Métodos** | Cómo construir técnicamente el software | Análisis, diseño, codificación, testing, UML, patrones |
| **Herramientas** | Soporte automatizado | *CASE*, IDEs, *CI/CD*, *version control* | {a Apuntes de Ingeniería de Software · Unidad 1}

## Disciplinas de la Ingeniería de Software

| Categoría | Disciplinas |
|---|---|
| **Técnicas** | Requerimientos, análisis, diseño, implementación, prueba, despliegue |
| **De gestión** | Planificación, monitoreo y control |
| **De soporte / protectoras** | Configuración, calidad, métricas | {a Apuntes de Ingeniería de Software · Unidad 1}

## Proceso de Ingeniería de Software

Secuencia de pasos para construir software según los requerimientos del cliente. Mejora el entendimiento del problema y la comunicación entre los involucrados. {a Apuntes de Ingeniería de Software · Unidad 1}

:::sintesis
- IS = enfoque sistemático, disciplinado, cuantificable para desarrollo, operación y mantenimiento.
- Crisis del software (1968): proyectos que fallan, exceden presupuesto/plazos.
- 4 capas: Calidad → Proceso → Métodos → Herramientas.
- Disciplinas: técnicas (reques, diseño, test...), gestión (planificación, control), soporte (config, calidad). {a Apuntes de Ingeniería de Software · Unidad 1}
:::
