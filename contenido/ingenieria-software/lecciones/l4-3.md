## Despliegue

Puesta en marcha del sistema en el entorno de producción, con instalación, configuración y capacitación de usuarios. {a Apuntes de Ingeniería de Software · Unidad 4}

Actividades clave:
1. **Plan de despliegue**: cronograma, *rollback plan*, comunicación.
2. **Entorno de producción**: servidores, red, seguridad, *backup*.
3. **Migración de datos**: *cutover*, validación, *rollback* si falla.
4. **Capacitación usuarios**: manuales, talleres, *help desk* inicial.
5. **Monitoreo post-despliegue**: *logs*, métricas, *alertas*, *hypercare* (soporte intensivo inicial). {a Apuntes de Ingeniería de Software · Unidad 4}

> **Regla**: siempre tener *rollback plan* probado antes de desplegar. {d}

## Tipos de mantenimiento

| Tipo | Qué hace | Ejemplo |
|---|---|---|
| **Correctivo** | Corrección de defectos detectados | Bug: login falla con password especial |
| **Adaptativo** | Adaptación a cambios en el entorno (SO, HW, regulaciones) | Actualizar por nueva versión de SO / ley de protección de datos |
| **Perfectivo** | Mejoras y nuevas funcionalidades | Agregar exportar a PDF, mejorar rendimiento |
| **Preventivo** | Reducción de degradación futura (refactoring, doc, tests) | Pagar deuda técnica, actualizar librerías, agregar tests | {a Apuntes de Ingeniería de Software · Unidad 4}

> **Distribución típica**: Correctivo ~20%, Adaptativo ~25%, Perfectivo ~50%, Preventivo ~5%. La mayor parte del costo de vida es mantenimiento. {d}

## Modelos de ciclo de vida

| Modelo | Características | Cuándo usar |
|---|---|---|
| **Cascada (Waterfall)** | Secuencial, fases completas al 100% antes de pasar a la siguiente | Requisitos estables, conocidos, regulados |
| **Prototipos** | Construcción de prototipos para validar requisitos | Requisitos poco claros, UI/UX crítica |
| **Iterativo** | Evolución progresiva en ciclos, cada iteración entrega funcionalidad | Proyectos medianos/grandes, riesgo medio |
| **Espiral** | Combina iterativo con análisis de riesgos en cada ciclo | Proyectos grandes, alto riesgo, innovación |
| **Evolutivo / Incremental** | Entregas parciales funcionales, crece el producto | Tiempo al mercado crítico, feedback temprano |
| **Ágil (Scrum, Kanban, XP)** | Ciclos cortos (sprints), entrega continua de valor, adaptación | Requisitos cambiantes, incertidumbre alta, feedback rápido | {a Apuntes de Ingeniería de Software · Unidad 4}

> **Regla**: no hay "mejor" modelo universal; elegir según contexto (requisitos, riesgo, equipo, tiempo, regulación). {d}

:::sintesis
- Despliegue: plan, entorno, migración datos, capacitación, monitoreo, *rollback plan*.
- Mantenimiento: correctivo (bugs), adaptativo (entorno), perfectivo (mejoras), preventivo (deuda técnica).
- Modelos: cascada (estables), iterativo/espiral (riesgo), ágil (cambiantes). Elegir según contexto. {a Apuntes de Ingeniería de Software · Unidad 4}
:::
